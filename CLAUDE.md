# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Always use Context7 for library documentation

**Use the Context7 MCP server to fetch current documentation whenever the task touches a
library, framework, SDK, API or CLI tool** — Vite, React, React Router, Tailwind, shadcn/ui,
Zustand, Swiper, react-day-picker, Sonner, the GitHub Actions used here. This covers API
syntax, configuration, version migration, library-specific debugging, and setup instructions.

**Use it even when you are confident you already know the answer.** Training data lags behind
releases, and this project sits on Tailwind v4 (CSS-first config, no tailwind.config.ts) and
React Router v7 with react-day-picker v10 — all of which changed their APIs recently. Prefer
Context7 over web search for library docs.

How:
1. `resolve-library-id` with the library name and the actual question — unless an exact
   `/org/project` id is already known.
2. `query-docs` with that id and the **full question**, not a keyword. One concept per call.
3. If the answer is thin, retry the same call with `researchMode: true`.

Do **not** use Context7 for: refactoring this codebase, debugging our own business logic,
code review, or general programming concepts.

## Commands

```bash
npm run dev          # dev server, http://localhost:3000
npm run build        # build to dist/ (no base prefix — for local preview)
npm run build:pages  # production build with base=/explorer-Iceland/
npm run lint
npm run typecheck    # tsc -b
```

Both build scripts run a `postbuild` hook that copies `dist/index.html` to `dist/404.html`.
That copy **is** the SPA fallback: GitHub Pages answers an unknown path with 404.html, the
shell boots, and React Router resolves the route. Without it every deep link is a dead end.

Preview the production build exactly as GitHub Pages serves it:

```bash
npm run build:pages
rm -rf /tmp/pagesroot && mkdir -p /tmp/pagesroot/explorer-Iceland
cp -R dist/. /tmp/pagesroot/explorer-Iceland/
npx serve /tmp/pagesroot -l 5000     # → http://localhost:5000/explorer-Iceland/
```

Always check this before touching deployment. Filter DevTools Network to 4xx — expect zero.

**Do not use `serve --single` or `vite preview` for that check.** Both apply their own history
fallback, which masks a missing or wrong `dist/404.html` — the exact thing being verified.
`serve` also only looks for `404.html` at its own root, so this recipe proves the base-prefixed
asset URLs but not the fallback; CI asserts `cmp dist/index.html dist/404.html` separately.

## Architecture

```
index.html    the shell; carries the <body> classes and the font preloads
src/
  main.tsx    entry
  router.tsx  the route table — createBrowserRouter, basename from BASE_URL
  index.css   Tailwind v4 theme, background @utility rules, @font-face
  routes/     RootLayout + one component per route + both error boundaries
  components/ layout/ cart/ product/ shop/ booking/ home/ auth/ ui/
  lib/        products.ts (accessors), cart-store.ts, dates.ts, alerts.ts, asset.ts
  data/       products.ts — the 12 tour records
public/       img/ video/ fonts/ icon.png .nojekyll
```

Routes: `/`, `/about`, `/shop`, `/shop/:id`, `/login`, `*`.

`components/ui/` is generated by `shadcn add` — treat it as vendored. Edits there are fine
(that is the shadcn model) but note them, because the next `shadcn add` of that component
overwrites the file.

The point of this structure is that the navbar, hamburger menu, cart drawer,
back-to-top button and footer exist **exactly once**. The pre-migration site had them pasted
into four HTML files with ~80 lines of duplicated inline script each. Do not reintroduce
per-page copies.

## Rules

**Never read `localStorage` at module scope or inside a render body.** The cart store is
created with `skipHydration: true` and rehydrated from an effect in
`components/cart/CartHydration.tsx`. That component is load-bearing: without it the cart never
rehydrates at all. Reading storage during render would also make the first paint depend on it.

**Tour ids must match `^[a-z0-9-]+$`.** Each id is a URL segment. A build-time assertion in
`lib/products.ts` enforces it — if it fires, slugify the id and keep the original as
`legacyId`. Note this now throws in the browser on first import rather than failing the build,
so it surfaces the moment you run `npm run dev`.

**Category is an explicit field on each tour.** Do not try to parse it from the id: every
original id was prefixed `hiking-`, including the sightseeing and outdoor-sports tours.

**Tailwind v4 is configured in CSS; there is no `tailwind.config.ts`.** The theme lives in the
`@theme` block in `src/index.css`. Do not add plugins casually — a plugin injects base styles
and can shift the whole design. Flowbite and daisyUI were removed for exactly that reason, and
it is also why `shadcn init` must never be run here: it appends an `@layer base` block that
restyles `body`. See [tech-stack.md](./tech-stack.md).

**The theme keys are camelCase and that requires `tailwindcss >= 4.1.18`.** Releases 4.0.0
through 4.1.17 silently dropped theme keys containing uppercase letters, so `--color-mainYellow`
would generate nothing and the site would render unstyled with no build error. CI greps the
built CSS for `bg-mainYellow` to catch a regression.

**Background images are `@utility` rules, not theme keys.** Tailwind v4 has no
`--background-image-*` namespace. They must stay `@utility` rather than plain classes, because
`ShopBanner` uses `md:bg-swiper-1` and variants only compose onto real utilities.

**Asset paths.** Vite applies `base` to everything it resolves — module imports, hashed assets
and `url()` inside CSS. It cannot see a plain `<img>`/`<video>` src, so those go through
`asset()` from `lib/asset.ts`. That helper strips the path's leading slash because `BASE_URL`
always ends in one: concatenating naively gives `//img/x.png`, a protocol-relative URL that
resolves to `http://img/x.png` and breaks every image. React Router's `<Link>` applies the
basename itself — never wrap a `to` in `asset()`. Product data stores bare `/img/…` so cart
entries stay portable.

**Convert dates with the local-time helpers in `lib/dates.ts`, never `toISOString()`.**
`onSelect` hands back a `Date` at local midnight; in UTC+8 `toISOString()` on that returns the
previous day, i.e. it books the wrong date.

**`onSelect` returns `Date | undefined`.** react-day-picker clears the selection when the user
clicks the already-selected day. The `undefined` branch must clear the parent's state, not be
ignored. The picker is fully controlled and holds no selection state of its own.

**Zustand selectors that build a new array or object must be wrapped in `useShallow`.**
v5 compares with `Object.is`, so a fresh reference each render makes `useSyncExternalStore`
loop — "The result of getSnapshot should be cached to avoid an infinite loop".
`selectBookedDates` is the one that needs it today.

**Alert helpers are synchronous and return void.** There is nothing to await. (They used to
lazily load SweetAlert2 over the network, and so had to be fired-and-forgotten in case a failed
chunk load let an invalid booking skip a validation `return`. Sonner is bundled, so the
property is now structural — keep it that way.)

**A modal built on Radix must still call `useHtmlScrollLock`** (`lib/use-html-scroll-lock.ts`).
Radix locks `<body>` and compensates for the scrollbar width, but not `<html>` — and the shell
gives `<body>` `h-screen`, so the document element is the real scroll container. Without it,
Space or arrow-down still scrolls the page behind the modal. The hook must **not** also touch
`<body>` or add padding: doing both applies the scrollbar compensation twice and shifts the
page ~15px on Windows and Linux, which is invisible on macOS overlay scrollbars. Pair it with
`overscroll-contain` on the overlay's own scroller to stop scroll chaining.

**The site has no dark mode.** Never add `class="dark"` to `<html>`, and never delete the
`@custom-variant dark` line in `src/index.css`. Tailwind v4's default `dark:` variant is
`@media (prefers-color-scheme: dark)`, and shadcn's components are full of `dark:` utilities —
without that line they fire for every visitor whose OS is in dark mode, resolving against
values this project never defines.

**Don't reintroduce duplicate `id` attributes.** The old `<template>`-cloning approach repeated
`id="cartTitle"`, `id="productImg"` etc. once per row. Use props and `className`. Keep an `id`
only where it is a real anchor or CSS target.

## Conventions

- Path alias `@/*` → `src/`. It is declared in **both** `tsconfig.app.json` (for the compiler)
  and `tsconfig.json` (because the shadcn CLI resolves it from the root config; without it
  `shadcn add` writes into a literal `./@/` directory).
- `PascalCase.tsx` for components, named exports.
- Business rules (3% tax, `today + 14` minimum date, group-size caps) belong in `lib/`, not
  inline in a component.
- Per-route `<title>`/`<meta>` come from `<PageMeta>`, using React 19's native hoisting. React
  does **not** deduplicate them: render exactly one per route, none in `RootLayout`, and keep
  `index.html` free of a `<title>` or it wins over every route forever.
- Content strings use `’` (U+2019) and `&nbsp;` (U+00A0) in places — preserve them verbatim
  when editing `data/products.ts`; letting an editor normalise them visibly shifts text.
